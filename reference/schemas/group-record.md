# Artifact schema — C23 `groups/<group>.md`

The reusable-group record — one file per named set of people, held across trips rather than assembled inside each one. It is the **second class in the model that is not per-trip**, and the second whose store is git-ignored, so the tracked witness under `examples/` is the only instance this gate can ever reach. `reference/adr/ADR-016-reusable-groups.md` is authoritative for the decisions behind it.

The fenced block below is the machine-readable half; `scripts/validate-artifacts.sh` reads it and holds no copy of it. Everything outside the fence is rationale.

```artifact-schema
class-id: C23
artifact: groups/<group>.md
schema-version: 1
path-pattern: groups/*.md
path-pattern: examples/*/groups/*.md
witness: examples/people-library-demo/groups/grp-4a81.md

# The universal block — reference/data-architecture.md § 4.4. No class removes a
# universal field; a class may only narrow one, and each narrowing is stated below.
field artifact: required string
field schema-version: required integer
field trip: required slug
field writer: required slug
field lifecycle: required enum [accumulate-append|rebuilt-each-synthesis|versioned|persist-mutable|output]
field provenance: required enum [human|researched|derived|recorded]
field publish: required enum [bound|internal|internal-hard|output]
field generated: optional date

# Class fields: none. The membership list is body-scoped — see the boundary note below.
```

- **This class ships the eight universal keys and no class field at all, and the absence is the design rather than an omission.** The record's whole content is a repeated relation — a list of member ids — and § 4.2 applied to a *single* id would admit it to frontmatter, so the boundary test alone does not settle this. Three other grounds do. **The unit is a repeated relation, not a value**: `reference/data-model.md`'s `Scope` axis distinguishes `slot` from `block`, and every `block`-scoped field in the corpus lives in the body. **Frontmatter-only placement would leave the class's entire content in its header and its body empty**, which no class in the corpus does. And **the membership rule the guard reads is a single anchored body regex**, which is the cheapest possible enforcement of the one criterion this class exists to hold. `reference/schemas/satisfaction-metrics.md` does type a `required list<slug>` field, so the grammar admits `members:` and the option was expressible; it is declined on those three grounds rather than for want of a way to say it.
- **Three narrowings, and each is a value domain narrowed rather than a field removed.** **`trip:` is the reserved sentinel `cross-trip`** — the same sentinel C22 declares, **reused rather than extended**, so § 4.4's narrowing gains a second member and no new sentinel enters the corpus. It type-checks as the required `slug` and, exactly as C1's `block-owned` is not a writer id, it is not a trip slug and no tool resolves it to a trip directory. **`generated:` is `optional`**, because § 4.4 omits it on human-authored classes. **`writer` is `operator`** — typed, not enumerated; the assignment lives in § 1.1 and this schema does not restate it.
- **`writer: operator` rather than `human`, and the distinction is the class's, not a preference.** `human` is C3's and C22's slug and is reserved for a class whose *subject* authors it — the traveller writes their profile, the person writes their record. Nobody is the subject of a group record: it is a set of references an operator assembles through named verbs, exactly as `trip-log.md` is a register an operator writes through `/trip-record log`. That class's `W` cell is prose naming its verb, and this class's is the same shape.
- **The body carries the `# <H1>` display name and exactly one section, `## Members`.** Every member entry matches `^- psn-[0-9a-f]{4}$` — an id on a bullet, with no trailing text, no display name, no role and no note. **That one anchored regex is the whole of this class's membership enforcement**, and **the section set is closed at one**: there is no free-text section, no description slot, and no second `##` heading. Prose outside a section is not a section — the tracked witness carries a fixture disclaimer above its `## Members` heading, exactly as `reference/schemas/person-record.md`'s witness does, and that is the only text a real record ever has above it.
- **The record holds no personal data of its own, and no rule enforces it because none is needed.** A member's name, a role, a relationship, a note, a split, and anything a trip computes all classify `TRIP`, `DEST` or `PERSON` under `reference/data-model.md` § *Field Scope* — so **this form has no slot for any of them**, the same closed-by-construction mechanism `reference/schemas/person-record.md` names for the durable person form. What is owed is the negative assertion, not a rule: **the group form emits zero `PERSON`-class labels.**
- **The display name is absent from the member entry, deliberately.** A name beside an id would be a second home for that person record's H1, which § 4.3 bars — and it would go stale the moment the person is renamed. **Names are resolved at render time from each record's own H1**, so the file stays machine-shaped and the operator-facing surface stays readable. This is the shadow-source failure the person library's own first amendment already paid for once.
- **The membership edge runs group → person, one-directional, and the direction is forced.** A back-reference on the person record would be *group or party composition* — the first entry of that class's no-slot list — and it would survive deletion of the group, which is the same ground `reference/adr/ADR-012-people-library.md` § 5 gives for refusing a back-reference list there. One consequence is free rather than designed: **a person may belong to any number of groups**, because N records may each carry the id and nothing on the person side records the multiplicity.
- **Resolution of a member id is inherited, not invented.** A member id resolving through a `merged-into:` stub is followed to **depth 1**; a second hop is `MALFORMED`. A member id that resolves to nothing is `DANGLING` and renders **`UNDETERMINED`** — never *no such person*, and never silently dropped. **A person merge writes nothing under `groups/`**: resolution is lazy through the stub, which is the shipped posture and needs no new mechanism here.
- **No `merged-into:` field, and no merge or split for this class.** Same-named groups co-exist safely because their ids differ, and the operator's remedy is to add and drop members. A group merge would need survivorship rules for a set union that has no field conflicts to resolve, which is a mechanism with nothing to decide. **This is declared rather than left silent**, because silence about an operation a sibling class ships would read as coverage.
- **`publish: internal-hard`, and the class is the fourth member.** Never rendered in any form, including anonymized. A record holds person ids, which are the cross-trip join key; rendering a group in any form publishes that these people travel together, and the corpus already states why anonymization does not help — in a small named party, stripping the name does not strip the identification.
- **`lifecycle: persist-mutable`, and every mutation this class admits is one file updated in place.** A member is added or removed and the file survives; deletion removes the file and leaves nothing addressable here, because this class admits no stub. **Unlike C3 and C22 it is `persist-mutable` with a real emitting writer** — the creation verb writes its frontmatter block at creation — so it takes the ordinary writer-upgraded burden at § 7.6 rather than the permanently-tolerated-at-version-0 exception those two carry. That exception protects a file **no agent may write**, and this class's own commands write it.
- **An agent may write this file, and that is where the class parts company with C22.** C22's defining rule protects *authored values* — a person's own words about themselves. A group record holds no authored value: only ids the operator selects and a name they type. So the commands write it directly and the class carries an ordinary mechanical writer. **Reading a person record to resolve a member's display name is a read and stays one** — nothing here writes into `people/`, and no `group-*` verb declares a path under that store as a write or delete target.
- **Erasure reaches this class, and the disposition is remove-the-bullet with no tombstone.** `.claude/commands/trip-record.md` § `## erase <person-id>` carries the row and is authoritative. **No `per-<token>` is written here**: that token is minted per (person × trip) precisely so no stable cross-trip pseudonym survives, and writing one into a cross-trip store would rebuild the correlation the mint exists to destroy. Removal is safe because a member set is variable-length by construction and a smaller set is a valid one; where removal empties a group or leaves one member, **the group is kept and reported**.
- **The two `path-pattern:` lines are the store's two roots**, not a widened glob. `groups/*.md` is the store at the repo root; `examples/*/groups/*.md` is the tracked witness. **Anchoring is load-bearing in the way it is for C22 and is not for a per-trip class:** `.gitignore` carries `/groups/*` **rooted**, so the store's contents never enter the index and the witness under `examples/` does — a `**/groups/*.md` pattern paired with a widened ignore rule would leave this schema naming a file the selector cannot reach, which is a coverage claim the gate is structurally unable to contradict.
- **Coverage.** This class declares `witness:`, and it joins `examples/people-library-demo/` rather than opening a fixture root of its own: that root already holds the two person records a group's members must resolve to, and a group placed anywhere else would either duplicate them or reference records the gate cannot reach. From this commit a stripped or unversioned witness is finding `S6` — a fail-closed coverage regression — because the failing assertion is this declaration and not the skip predicate. The witness carries `artifact: groups/<group>.md`, the class string with its angle token, because that is the value § 1.1 declares; a witness naming its own path would be finding `A5`.
