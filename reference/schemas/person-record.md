# Artifact schema — C22 `people/<person>.md`

The durable person record — one file per person, held across trips rather than copied into each one. It is the **first class in the model that is not per-trip**, and the only one whose store is git-ignored, so the tracked witness under `examples/` is the only instance this gate can ever reach. `reference/adr/ADR-012-people-library.md` is authoritative for the decisions behind it.

The fenced block below is the machine-readable half; `scripts/validate-artifacts.sh` reads it and holds no copy of it. Everything outside the fence is rationale.

```artifact-schema
class-id: C22
artifact: people/<person>.md
schema-version: 1
path-pattern: people/*.md
path-pattern: examples/*/people/*.md
witness: examples/people-library-demo/people/psn-3c7e.md

# The universal block — reference/data-architecture.md § 4.4. No class removes a
# universal field; a class may only narrow one, and each narrowing is stated below.
field artifact: required string
field schema-version: required integer
field trip: required slug
field writer: required slug
field lifecycle: required enum [accumulate-append|rebuilt-each-synthesis|versioned|persist-mutable|output]
field provenance: required enum [human|researched|derived|recorded]
field publish: required enum [bound|internal|internal-hard|output]
field generated: optional date

# Class fields.
field merged-into: optional slug
```

- **The fence constrains frontmatter, and the record's own field set is in the body.** The person's durable answers — a passport's issuing country and validity, a standing need, a travel preference — are **body bullets**, not header keys. § 4.2 is what decides it: two correct writers given the same facts do not phrase *"United States, valid through March 2029"* identically, so question 2 fails and the value stays in the body. A `field Passport:` line here would declare a passport a machine-readable frontmatter key, which is both wrong by the boundary test and a worse privacy shape. This class ships the eight universal keys plus one class field, exactly as C3 ships the eight and nothing more.
- **Three narrowings, and each is a value domain narrowed rather than a field removed.** **`trip:` is the reserved sentinel `cross-trip`** — it type-checks as the required `slug` and, exactly as C1's `block-owned` is not a writer id, it is not a trip slug and no tool resolves it to a trip directory (declared at § 4.4, beside C1's and C14's). **`generated:` is `optional`**, because § 4.4 omits it on human-authored classes. **`writer` is `human`** — typed, not enumerated; the assignment lives in § 1.1 and this schema does not restate it.
- **`merged-into: optional slug` is the one class field, and it passes § 4.2 cleanly.** It is a reference to another record's key, so it is referential (Q1); it is an id, so two writers produce the same characters (Q2); and resolution branches on it — one hop to the survivor, then `MALFORMED` rather than a second hop (Q3). § 4.3 admits it because no other structural position in the file holds it. **A merge stub is this class's own file rewritten in place** — same frontmatter, plus this field, with the merge receipt as the body — so it validates as an ordinary instance of the class and needs no separate shape.
- **`publish: internal-hard`, and the class is the third member.** Never rendered in any form, including anonymized. C3 is `internal` because a trip's own guard walk reaches it; a person record holds the durable subset of the same values, across every trip rather than one, and nothing renders it.
- **`lifecycle: persist-mutable`, and it is the only token that admits deletion.** A record is a single file updated in place that survives every re-run. That definition's *no ghost row lingers* clause governs a row whose subject was removed from a trip; it is not a licence to leave a stub behind when a person is deleted. **Erasure deletes this file and leaves nothing addressable here** — the tombstone lives in the trips, never in the store. `merged-into:` is the one addressable remnant this class admits, and it is a different thing: a merge stub is addressable *on purpose*, so an archived trip still resolves through it.
- **No agent writes a value into this file, and that is the class's defining property rather than a policy.** Every value originates from the person, or from the operator relaying that person's own statement. No agent may compute, infer, enrich, summarise, translate or promote a value into a record; promoting a trip value is an explicit, confirmed human act, never a side effect of composition or enrichment. **Reading is permitted and required** — composition reads the record and writes the trip, never the reverse, which is what keeps a trip's local divergence from silently rewriting a durable fact. Exactly four mechanical writes are permitted, all operator-initiated and none authoring a value: the creation scaffold, the merge-stub rewrite, merge absorption into the survivor, and erasure. **This is also why the class is permanently tolerated at version 0** (§ 7.6): an engine upgrade pass is an agent write.
- **Provenance is field-scoped, and the artifact-level key stays `human`.** Self-authored versus operator-relayed is carried per field by the existing inline `[OPERATOR-PROVIDED]` mark — the shape `[ENRICH]` already ships as a field-scoped class inside a `human` artifact — and no enum widens, because § 4.4 declares `operator-provided` as **entry** vocabulary carried by the marks and not by the key. Record-level provenance has no correct value for the case this class exists to serve: someone captured as an operator-provided party member who later files their own answers. `human` would erase that some values were relayed; `operator-provided` would wrongly fence values the person wrote. **Two prohibitions follow and both are machine-checkable: a field outside the record's `## Needs` section may not carry an operator-provided mark**, which is what bounds an operator-provided record to needs only, across a merge as well as at creation — and **`[THIRD-PARTY]` is refused anywhere in this class.** A cross-trip record about someone who never spoke is the consent boundary `reference/adr/ADR-006-third-party-data-capture.md` draws, at wider scope. A mark records that a value was relayed; **it never establishes that its subject agreed to it being kept.**
- **The validity horizon is `[VALID-THROUGH <YYYY-MM>]`, a suffix mark admissible on any field bullet and required on none by this schema.** Month precision is a decision: the intake form asks for a passport's issuing country and *"the month it's valid through — never the number"*, and a durable store must not demand more precision than the per-trip form it replaces. Zero-padded `YYYY-MM` compares lexicographically **and** chronologically, so *expired* is a string comparison against `strftime('%Y-%m', today)` with no date library — which matters on a pure-bash guard surface. **An expired field composes to `UNKNOWN` and is reported**: never silently used, because a plan would then check entry requirements against a lapsed document, and never silently dropped, because a vanished constraint reads as compliance. In a merge, expired loses to live without prompting — the one deterministic survivorship exception, and it works only because expiry is machine-determinable.
- **Identity is the surrogate `psn-[0-9a-f]{4}`, borne in the filename, and the display name is the H1 and nothing else.** § 4.3 bars restating a value that already lives in a structural position, and the H1 is the position the identity rule keys on, so the name never enters frontmatter. **Creation refuses when a new record's normalized H1 equals a live record's**, on exact equality after § 3.2's existing normalization — never similarity, never edit distance, never fuzzy matching — with three named remedies: link to the existing record, disambiguate the display name, or create anyway with the collision acknowledged. The normalization is the one the publish guard already executes; **a second implementation would be a second source of truth for identity.** The refusal reads a name and refuses a *creation*; merge reads two operator-supplied ids and never reads a name, so no code path runs from a name comparison to a merge.
- **The record is strictly one person, and no rule enforces it because none is needed.** Group and party composition, any split, computed values including desire overlap, trip history, and a second person's data all classify `TRIP` or `DEST` under `reference/data-model.md` § *Field Scope* — so **the durable form has no slot for any of them**, the same closed-by-construction mechanism that makes a `PERSON` field non-overridable. What is owed is the negative assertion, not a rule: the durable form emits zero `TRIP`/`DEST` labels.
- **The two `path-pattern:` lines are the store's two roots**, not a widened glob. `people/*.md` is the store at the repo root; `examples/*/people/*.md` is the tracked witness. **Anchoring is load-bearing in a way it is not for a per-trip class:** `.gitignore` carries `/people/*` **rooted**, so the store's contents never enter the index and the witness under `examples/` does — a `**/people/*.md` pattern paired with a widened ignore rule would leave this schema naming a file the selector cannot reach, which is a coverage claim the gate is structurally unable to contradict.
- **Coverage.** This class declares `witness:`, and `examples/people-library-demo/` is a **new** fixture root rather than a row in the existing one: `examples/data-architecture-demo/` is a *trip* root, and a cross-trip record placed inside one would re-teach the scoping this class exists to break. From this commit a stripped or unversioned witness is finding `S6` — a fail-closed coverage regression — because the failing assertion is this declaration and not the skip predicate. The witness carries `artifact: people/<person>.md`, the class string with its angle token, because that is the value § 1.1 declares; a witness naming its own path would be finding `A5`.
